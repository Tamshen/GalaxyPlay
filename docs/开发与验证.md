## 范围与模块

仅面向吉利银河 L7（2023 / 2024 款目标配置）、8155、Flyme OS / Android 11，最低 Android 10。屏幕规格为 13.2 英寸、1440×1920、3:4；运行窗口、密度、权限与硬件能力均运行时获取，不能由年款推定。每种固件单独验收。

| 模块 | 职责 |
| --- | --- |
| `shared` | DiPlay 协议、传输、认证和媒体核心 |
| `common` | 宿主、设置、原生组件与 L7 接入 |
| `mobile` | L7CarPlay APK 入口，包名 `com.ecarx.carplay` |
| `e2e` | 单元、组件、设备场景及交付检查 |

应用版本与 DiPlay 核心基线唯一维护于 [版本配置](../gradle/l7-version.properties)。核心是仓库内源码模块，不依赖工作区旁边的 DiPlay 目录。保留上游署名与许可，不启用其他车型入口、HUD 或车辆控制。

UI 设计与离线示例维护于工作区 `FlymeAutoOS/UI/l7carplay/组件示例.html`，完整契约为同目录 `界面规范.md`。产品仓库保留 Android 原生组件和测试，HTML 不进入 APK、构建依赖或站点发布。组件职责见 [AGENTS.md](../AGENTS.md)。

## 运行约束

- 会话控制器、视频 worker、音频模块分别持有连接、MediaCodec、AudioTrack/AudioRecord；回调校验会话代次，退出幂等释放，不在 UI 线程等待资源退出。
- 无线采用 Android 原生热点与 MANUAL 接入，区别于车机桌面热点。连接设置自动尝试读取配置，用户可主动开启或应用生成配置；开启中的热点不重配，退出不关热点。不静默切换 P2P 或 LocalOnlyHotspot，有线连接与认证分别验收。
- 首次协议、USB、自动连接和服务入口统一检查同意状态；协议正文唯一维护于 `common/src/main/assets/l7-first-use-agreement.md`。
- 进入设置、改变 UI 密度或昼夜主题只刷新控件，不停止会话或重建视频 Surface；撤回协议与退出清理全部服务和悬浮窗。
- 面板规格换算约为 201×268 mm；按视频区域占真实显示像素的比例上报物理区域，不用 UI DPI 或编码档位虚增毫米值。此数值属于规格换算，非实物测量。
- 临时缩窗及恢复到启动窗口以内保持原连接画布；真正旋转、系统栏设置变化或超出启动窗口才重连。重建前等待窗口稳定并重查权限，触控继续使用同一等比矩形。
- 视频矩形、crop、旋转和触控采用同一变换；按实际窗口、Insets、density、fontScale 布局，等比显示允许黑边，零窗口不协商，避让区域不重复计入 safeArea。

自动连接启用时，Application 在 Activity 构造前同步写入启动标记。连续 3 次未完成启动或连接即关闭自动连接；Java 异常保存类型与最多 8 个本项目栈帧，Android 11 结合本进程退出记录识别 native/ANR，已知主动停止与系统回收不累计。Android 10 或退出信息缺失时按未完成标记保守恢复。首页前台无会话或当前连接连续稳定 30 秒后复位；主动取消、退出复位。保护状态拦截任务恢复与 USB 直接拉起，用户可从首页手动连接，明确重新开启自动连接才解除保护，不清除配置或认证。

USB 访问授权按设备与独立请求编号绑定；重复发现不重复申请，授权广播与轮询只消费一次。控制器重建使用独立广播 action，PendingIntent 的 data 隔离请求，重连／关闭使旧请求与已排队任务失效，已排队的旧失败提示也不交付给新尝试。成功回调仍复查实际权限，拒绝、撤销和轮询异常转为失败；重枚举／接口打开回调核对连接代次与当前阶段，迟到打开的 USB 会话关闭。iPhone 与 CH341 的授权 PendingIntent 允许系统填入设备和授权结果，固定应用包与 action；Android 12 起显式使用 MUTABLE；按 [PendingIntent 填入规则](https://developer.android.com/reference/android/app/PendingIntent#FLAG_IMMUTABLE)保留系统交付能力。设备路径只在内存比较，不进入新增日志。依据 [Android USB 授权契约](https://developer.android.com/reference/android/hardware/usb/UsbManager#requestPermission(android.hardware.usb.UsbDevice,%20android.app.PendingIntent))，断开后授权需要重新取得；不缩短既有授权、重枚举及控制等待预算。

USB 连接不要求热点配置；VPN 仅接管本应用，添加应用失败不回退到全局 VPN。AirPlay 首选端口被占用时尝试 7001～7010，再由系统分配临时端口；Bonjour 与 iAP2 使用实际端口。无线蓝牙只承担认证和 Wi-Fi 引导，定位由运行隧道自行订阅，缺少 GPS 方向时不伪造朝北。

有线启动用独立 `L7VpnConsent` 处理 VPN 准备、页面启动及返回。等待期间将尝试号交给宿主保存，重建后由原 ActivityResultRegistry 交付，不再另开授权页；同进程最新未结束尝试沿用日志编号，新进程另建记录以保留旧 PID 退出证据。成功返回后复查真实 prepare 状态，仍需授权时失败且不循环申请；无线切换、取消、重复及销毁后的返回不启动有线。已处理的麦克风许可不因恢复再次申请，定位按恢复时实际状态核对。页面不存在、系统拒绝、调用异常与拒绝／取消分别记录，失败不继续创建连接，并提供重试、返回有线设置和日志入口。`L7WiredJournal` 保留最近两次尝试，每次至多 24 个阶段锚点，保留首个启动与最新事件并标记淘汰数；少量关键调用前和失败／崩溃同步保存，普通阶段异步保存。手动连接也记录 Java 异常类型及最多八个本项目帧，不依赖自动连接开关；新进程按旧 PID 与启动时间查询本应用退出原因，未知仅称异常结束／未完成，已确认主动退出及系统回收不弹成崩溃。日志查看、主动上传及导出均包含有线摘要；上传在预算内优先保留摘要及数字退出记录，清空日志也清除独立摘要。[USB-01](<../../TODO/P0 L7CarPlay USB有线启动与崩溃诊断TODO.md>) 保留修复效果与全链路实车验收；原版／博越同一 VPN 入口没有专项异常保护。既有大型宿主仅接入生命周期和 UI，授权状态与持久摘要已拆入独立组件。

诊断写入使用一个后台线程、最多 64 条待写记录，拥塞时淘汰最旧记录。记录连接阶段、接口及接收计数、慢读取、资源关闭耗时和麦克风读写计数，不记录协议或语音载荷。Android 11 导出最多三条本应用进程退出原因与内存数值，不读取系统堆栈或描述；内核 UDP 计数属于整机，不能视作 CarPlay 独立丢包率。

### 视频与恢复

默认单路 H.264 硬解、30 fps，压缩队列 → MediaCodec → Surface。筛选 MIME、profile、尺寸方向、对齐、帧率和实际初始化结果；HEVC、60 fps 及高分辨率需单独验收。保持有界队列，不增加常态转码、逐帧 Bitmap/JPEG 或像素回读。

| 项目 | 约束 |
| --- | --- |
| 队列 | 60 帧 / 8 MiB 硬上限，接收、排队、输入等待共用 250 ms 帧龄预算 |
| 参考帧 | 丢失后重同步并等待关键帧，请求频率不超过每秒一次 |
| HEVC | hvcC / Annex B 转为 csd-0，缺 VPS/SPS/PPS 拒绝配置；至少三帧输入后，八秒无输出或呈现分别诊断 |
| 恢复 | 连续失败最多四次，250/500/1000 ms 退避；稳定输出十秒或显式新目标重置预算 |
| Surface | 所有 worker 异步解除旧目标后再释放；旧回调不能提交到新目标 |
| 统计 | 接收、输入、提交、呈现回调分开；提交和回调均不等于物理面板测量 |

HEVC 失败提示选择 H.264 后重连，不静默更换解码 MIME。后续降帧率、降画布必须通过重协商或重连生效，本地缩放不等于手机负载降低。

### 音频与按键

| 用途 | 默认策略与候选 |
| --- | --- |
| 媒体 | MEDIA；系统路由 |
| 导航 | ASSISTANCE_NAVIGATION_GUIDANCE；系统路由 |
| Siri | ASSISTANT / VOICE_RECOGNITION；输入输出均交给系统 |
| 电话 | VOICE_COMMUNICATION；系统选择输入输出 |

音频方案由 `common/src/main/assets/audio-templates/` 下的 `l7.json`、`l7-bus.json` 与 `l6.json` 驱动；从系统 Build.DEVICE／PRODUCT／MODEL 的完整标识自动识别 g636 为 L7、g733 为 L6；信息未知或冲突不猜测。首次识别必须二次确认后才保存，选择保留当前车型也会记录已审阅以避免反复询问；音频页可手动选择和重新确认识别结果。主入口自动连接、手动连接及 USB 宿主创建新会话都经过确认，现有会话快照保持。日志只记录标准车型及识别／确认阶段，不记录固件原文。L7 保留原 `mode` 和 `audio-template.json`，L6 使用独立 `mode_l6` 与 `audio-template-l6.json`，自定义文件分别原子写入。L6 三用途采用用户确认原厂互联的标准输出角色：音乐 1／music 2、导航 12／speech 1、助手 16／speech 1；电话保持既有通信用途 2，铃声保持 CarPlay 原有属性。模板焦点按音乐 GAIN、导航／铃声 MAY_DUCK、电话／助手 TRANSIENT 处理。L6 未确认物理 BUS，内置地址为空，不复制 L7 地址。选择、编辑确认后保存；导入经有界读取、UTF-8 与 schema 校验并确认，失败保留原文件。内置模式隐藏技术参数，自定义模式才显示文件编辑、导入／导出及三用途的 0／1–20／101–103 调试选项。切换内置模式不覆盖自定义，恢复默认也保留该文件。首次迁移保留旧的自定义音道和额外 BUS 选择；连接时固定一份不可变模板，试听共用设备选择规则。

JSON `version=1`，`name` 最多 64 字符，`preferBus` 为布尔值；`choices` 仅含 `media`、`navigation`、`assistant`，值为策略键：0 为原厂默认，1–20 为传统流，101／102／103 分别选择标准媒体／助手／导航用途；`outputBuses` 可含上述三用途及 `phone`、`ringtone` 的 BUS 地址。可选 `focusGains` 按音频角色定义焦点 1–4，电话只接受短时焦点 2；省略该字段时沿用既有焦点，旧模板格式不变。电话用途固定为通信，文件不能覆盖输入源或设备 ID；未知字段、非法策略／焦点、私有地址及超过 16 KiB 的文件被拒绝。

L7 配置保持系统设备选择，不调用 `setPreferredDevice`；L7 BUS 或自定义显式开启后才尝试配置地址。内置输出分别为 `bus0_media_out`、`bus1_navigation_out`、`bus2_voice_command_out`、`bus3_call_ring_out`、`bus4_call_out`，依据已采集固件配置；不再沿用与该批 L7 不匹配的 `BUS00_MEDIA` 等名称。按当前枚举的地址、方向、格式和唯一性选择，缺失或拒绝回退系统。录音沿用系统与原厂输入源回退，不猜测输入 BUS；传统流不叠加 BUS。不修改车机 XML，不硬编码 deviceId，不调用未经 L7 验证的 duck/unDuck、HAL 或音量组接口。实际路由监听始终保留，偏好请求返回与最终 routed device 分别记录。配置地址匹配不等于物理头枕输出通过。

L7 头枕交给原车模式与音频策略分配，需配合“驾享”模式实测，不固定绑定传统流 6，也不添加独立头枕焦点算法。usage、传统流与设备 ID 分开标注。

三用途设置只覆盖输出策略，协议角色独立；legacy 策略不叠加 BUS。音频配置与焦点处理参考博越 DiPlay v0.2.11：焦点及高级映射默认开启；标准用途预设默认媒体 1、导航 12、Siri 16，电话固定 2；博越 legacy stream 14 保留手动选项。电话 > Siri / 铃声 > 导航 > 媒体；L7 媒体申请 GAIN，其余申请 TRANSIENT；L6 导航／铃声按模板申请 MAY_DUCK，电话／助手仍为 TRANSIENT；导航把媒体降至 0.2，其他优先流抑制低优先流。系统 CAN_DUCK 叠乘降音、GAIN 恢复；永久 LOSS 抑制媒体，明确播放才允许恢复请求，不在失焦回调内抢焦点。会话关闭和旧监听器继续隔离。

标准用途预设直接使用 Android usage；选择原厂用途时框架 `AUDIO_USAGE_CP_*` 优先，其次 `/vendor/etc/carplay/carplay_config.json` 的 `AudioAttrs`，最后标准 Android 用途；读取最多 64 KiB，只保留音频段，不记录正文。忽略把非媒体全部映射为 MEDIA 的模板。Siri / 电话输入按有线、无线和带宽查找 `AUDIO_SOURCE_*`，拒绝或录音启动失败释放后回退标准源。试听共用配置、流拒绝回退和焦点，设备是否真正发声仍需实车确认。

模板升级迁移保留现有自定义输出；“恢复用途路由”切回当前所选车型的默认配置，恢复缓冲 300 ms、音频焦点和通话音效，并保留自定义模板、配对与认证。协议协商和编解码仍用官方核心基线，不移入 KX11 / Android 9 专属分支。

E5 无线实时下行参数对齐：`CarPlayE5` 的 Phone／Alert／Legacy Siri／Enhanced Siri Aux／Alternate 无线配置均为 80 ms 协议抖动目标；L7 仅在无线非主音乐角色使用 RTP 样本时钟建立该目标，突发包沿同一时钟排队，迟到包不再累加 80 ms。设备容量另按原厂普通分支 40 ms 请求，尊重 AudioTrack 系统最小值与实际获批容量，首个 PCM 帧写入后启动；不再套用旧实时轨道的 16 KiB 容量／4 KiB 启播下限。`Audio: ready` 记录 wireless、jitterTargetMs、实际 bufferMs 和 startMs。原厂 20 ms 分支有额外条件，未作为全局值；主音乐属于 Buffered Audio，未找到可核实的原厂无线预缓冲时长，仍保持独立媒体配置；视频队列容量与轮询超时不解释为播放延迟。本轮不调整有线参数，也不以有线数值比较无线延迟。目标参数对齐不等于复刻原厂抖动算法或完成实车延迟验收。

通话默认尝试系统 AEC/NS，可在音频设置关闭，下次连接生效；输入交给系统，BUS 模板只对下行输出尝试首选设备。仅普通模式可临时进入 MODE_IN_COMMUNICATION，不覆盖原车通话、响铃或其他通信来源；最后一条通话录音停止后，仅当模式仍为本模块设置值时恢复。音效不可用、模式设置被拒绝或诊断失败不阻断录音，Siri 保持原录音路径。Android 公共 API 不能区分其他应用重新写入相同模式的情况，实车需验证与蓝牙通话共存。

通话组件使用 `Audio: callLifecycle` 关联启动、停止请求和本地释放流程，`callRun`／`callEpoch`／独立组件令牌区分会话与迟到回调；最后一个上／下行组件释放后才记 `AFTER_RELEASE`，关闭会话记 `CLOSED`，Siri 不创建通话轮次。音乐沿既有五秒窗口及结束统计另记 `Audio: mediaRecovery`，包含通信模式、焦点用途／获焦／抑制、组件计数和距最后释放的时间，与输入间隔、写入、队列和 underrun 对照。诊断只读、默认沿现有可上传日志回调，不增加线程或 PCM 存储；本地释放流程和焦点观测不等于手机挂断、实际声音或系统策略完全恢复。

歌曲信息保留 iAP2 增量字段，首次暂停必须发布。系统 MediaSession 只在歌曲/封面变化时更新元数据，进度不重复传送图片，也不额外申请音频焦点。封面单份最多 2 MiB，传输及解码队列各最多四份，解码尺寸限制为 384 像素，旧会话回调丢弃；不新增常态视频像素回读。

蓝牙互斥只针对本次已确认手机的 A2DP，保留 HFP、配对和其他设备。自动交接开关即时更新当前会话的既有保护器；关闭使待断开确认失效，仅释放已有明确播放请求，暂停仍取消等待。重新开启检查当前目标状态，快速切换不重置尝试预算；关闭／失败的旧保护器不能重新启动。隐藏接口按权限和真实结果降级；查询最多六秒，断开确认最多三秒，每会话至多两次。等待只保留最后一次明确播放，暂停取消待发命令，超时恢复手动路径，不因断开完成自动播放。USB 未确认目标时不自动断开。

方向盘标准媒体键使用 MediaSession；语音广播 `action_steering_wheel_controller_event` 的 type 3/4 按长短按处理，仅转发真实 CarPlay 会话，短按按助手状态处理，300 ms 内去重；不直接映射广播 1/2。厂商按键和焦点仍需实车验证。

方控诊断使用 `STEERING_TRACE`，按本次进程 run、trace、会话 generation 关联输入、OEM 主线程交付、跨入口去重、蓝牙等待／取消、发送队列及通道写入；累计 elapsedMs 使用单调时钟。手机播放状态和音频流状态独立观察，不能作为命令 ACK。调试页保留 256 条阶段并显示最近 12 组，手动标记失效／正常，进入页面不发命令或上传。专用 `steering.log` 经既有有界异步写入器脱敏落盘，每份最多 512 KiB，最多保留当前加两份历史，纳入既有日志查看与手动上传；清空本页只清内存显示，日志维护的清除操作覆盖专用文件。

语音输入测试复用标准 AudioRecord，默认 VOICE_RECOGNITION，可手动选择 MIC／VOICE_COMMUNICATION；16 kHz 单声道 PCM16，只在前台显式启动，最长 10 秒，非阻塞读取。离页／后台请求停止，同一 worker 完成释放后才允许下一轮；已有协议麦克风时不启动，通话／Siri 接管或权限撤销时结束本地采集。不更改通信模式、不保存 PCM、不做回放或本地识别。页面显示电平、零样本比例、设备类型与系统静音，Siri 按钮复用当前真实会话请求，入队与发送计数不解释为手机识别成功。`VOICE_TEST`／`VOICE_SIRI`／`VOICE_UPLINK` 只记录技术摘要，协议日志按当前会话所有权过滤迟到回调；页面环形历史 32 条、显示最近 6 条，`voice-input.log` 每份最多 512 KiB、当前加两份历史，纳入日志查看／导出／用户主动上传及清除；清空页面只清显示历史。

麦克风只在 Siri / 通话需要时采集，结束释放；只统计状态和能量摘要，不保存人声。Opus 48 kHz 路径需核对协商格式；成功读取或有能量不能证明手机收到可识别语音。

## Docker 构建

使用 `mobiledevops/android-sdk-image:latest` 和仓库 Gradle Wrapper，编译、测试、lint、打包均在 Docker 中执行。先启动 OrbStack 或 Docker Desktop，在仓库根目录运行：

```bash
# Apple Silicon 默认 ARM64 一次性容器，仅打包。
bash scripts/build-l7-host.sh
# 构建成功后复用 AVD、覆盖安装并打开。
bash scripts/build-l7-host.sh --preview
# 完整单测、mobile lint、内置认证 APK；默认 amd64。
bash scripts/build-l7-host.sh --check
# 无本地认证时显式生成源码验证包。
bash scripts/build-android-docker.sh --source-only
# 自定义任务，筛选方法见 e2e/README.md。
bash scripts/build-android-docker.sh -- :common:testDebugUnitTest
```

默认执行 `:mobile:assembleStandaloneDebug`，缺认证输入即停止；源码验证包执行 `:mobile:assembleDebug`，安装后需配置认证。调试输出 `mobile/build/outputs/apk/debug/mobile-debug.apk`。普通自定义任务不默认挂载认证，指定 standalone 任务或认证环境变量时才挂载。 交付实车测试包使用默认／standalone 入口；将回归、lint 和打包合在自定义任务中时，使用 `:mobile:assembleStandaloneDebug`，确保挂载认证并执行必需材料检查。

工具链由 [Dockerfile](../docker/Dockerfile) 和 [ARM64 Dockerfile](../docker/Dockerfile.arm64) 管理：SDK 37、Build Tools 36.0.0、NDK 28.2.13676358、JDK 25。ARM64 调试为原生 Java/Gradle 加 x86 SDK 工具的混合路径，容器架构与 APK 的 `arm64-v8a` ABI 分开。`latest` 不代表固定镜像，实际摘要保存到本地构建记录。

`--amd64` 可切回完整检查路径；底层快速打包为 `bash scripts/build-android-docker.sh --arm64 --standalone`，架构参数放在模式或自定义任务前。构建容器成功、失败或中断后自动停止并删除（`--rm` 加本次 CID 退出清理），不保留 Gradle 常驻进程；旧 `--warm` 参数仅兼容调用。SDK 镜像、Gradle 磁盘缓存和签名卷保留，不例行 clean 或删除缓存。不混入 macOS SDK/NDK/JDK，入口拒绝本机 `local.properties` 路径；不并发写构建输出。

| --- | --- |
| `docker/` | 镜像构建上下文，不含源码与认证 |
| `l7carplay-gradle-amd64` / `l7carplay-gradle-arm64` 卷 | 分架构工具链和 Gradle 缓存 |
| `l7carplay-debug-signing` 卷 | 持久化调试签名，删除后可能无法覆盖安装 |

### 原生热点接入

`NativeHotspotConfiguration` 隔离 Android 10 的 WifiConfiguration 和 Android 11 的 SoftApConfiguration；读取失败或密码被掩码时不覆盖已保存值，识别 OPEN/WPA2/WPA3 安全类型。`L7WirelessHotspotGate` 在无线连接入口等待准备结果，成功才继续建链，缺权限或接口不可用时提供原生设置与手动配置；USB 不经过该预检。`L7HotspotTask` 单线程串行执行、按代次丢弃旧结果，系统明确接受后才原子保存名称、密码与安全类型。开启使用 Android 11 TetheringManager 回调，Android 10 保留旧启动路径；回调成功后仍等待真实 AP 开启状态，最多 15 秒。CarPlay 后续通过既有 ManualHotspotManager 等待接口地址，不把热点开启当作投屏连接成功。

`NativeHotspotConfiguration` 的写入日志分别保留 setter 布尔返回、异常类型，以及可用回读是否匹配；系统接受但不可回读不标记为已确认一致。`CarHotspotTethering` 分别记录已开启、请求启动、接口返回、回调原码、实际状态确认及最终结果，附 AP 状态原值；热点就绪仍不代表手机已连接。日志不包含 SSID、密码或异常正文。

`L7WirelessPrerequisites` 在无线页顶部和连接前检查蓝牙开关、读取权限与已选择设备的配对有效性；不要求 A2DP 媒体连接。有线走 USB iAP2，不经过蓝牙门槛。

`settings-connection` 仅承载方式选择；无线和 USB 分别使用独立子路由与三步引导，返回到方式选择。`L7HotspotActions` 由 Activity 持有，复用统一任务弹窗，读取/开启/写入的失败持续显示并提供恢复入口，配置接受与 AP 开启分别记录；后台停止等待，普通页面重绘保留窗口。`L7WiredSettings` 在工作线程只读 USB 枚举与权限，进入页面不发送指令、不申请权限；开始连接前重检，设备缺失需明确确认才进入等待，不支持或查询失败不会启动会话，后台和销毁按代次丢弃迟到结果。既有核心仍负责 USB 权限和设备重枚举。

Android 11 的开启路径接受 WRITE_SETTINGS 或系统级共享权限，而读写 SoftApConfiguration 涉及 NETWORK_SETTINGS；普通修改系统设置授权不能替代。只按应用自身身份调用，系统拒绝或隐藏接口不可用时返回手动配置。保留独立 ACTION_WIFI_SETTINGS 入口且不限定处理包名，允许 Flyme 设置接管；Wi-Fi action 不可用时回退 ACTION_WIRELESS_SETTINGS。原生热点直达失败提供 Wi-Fi 恢复按钮；读取失败保留已存凭据，不能推断 AP 关闭或写入不支持。依据：[AOSP TetheringManager](https://android.googlesource.com/platform/prebuilts/fullsdk/sources/android-30/+/refs/heads/androidx-main-release/android/net/TetheringManager.java)、[Android 11 系统 API](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android11-release/api/system-current.txt)。模拟器不能代替 L7 固件的接口权限与无线建链验证。

### 应用内基础调试

设置首页分别提供「调试」与「日志」。调试承载环境检查、方控、语音和报告历史；日志页顶部提供查看、上传、清空日志和清空报告，复用唯一上传任务及原有导出、悬浮窗和服务器配置。L7LogView 在后台读取快照，以虚拟列表显示，支持搜索高亮和分段复制，打开页面不上传。`settings-logs` 为日志独立路由，旧 `settings-debug-logs` 重定向到该页；旧 `settings-diagnostics` / `diagnostics` 仍到 `settings-debug`。结果和历史沿用 `settings-debug-results` / `settings-debug-history`。调试子页返回调试，调试与日志分类均返回设置，侧栏归设置。页面、采集、存储与导出由独立组件管理；既有 DiPlayActivity 仍超过职责规范，本次保留连接和渲染逻辑。

应用启动即初始化默认 `debug.log`；普通调试事件与采集逐项事实默认脱敏后经有界异步队列写入，512 KiB 轮转、当前加两份历史。方控与语音沿用各自专用文件并共享同一队列，避免重复落盘；基础检查另保留最新与上一批事实日志，单批 512 KiB，以覆盖队列突发丢弃的可能；超预算明确标记截断。查看、导出与用户主动上传包括这些文件。清空展示报告不删除日志；清空日志丢弃旧队列代次，后续调试仍可重新记录。原始音频、协议载荷和凭据不入日志。

`L7ProbeRunner` 使用一个后台工作线程，15 秒总预算；取消或超时后拒收迟到结果，等待尚未返回的查询释放后才允许再运行。基础检查只读取当前应用及可见系统状态，不启动厂商服务、授权、测试输入或认证网络。`L7PermissionProbe` 按原名查询权限，分别保留定义可见性、保护级别原值/解析值、声明、普通授权、AppOps、特殊访问及未验证的有效调用；查询异常只记录类型，未知值为 null 加原因，获授只记观察证据。候选目录包含 163 个权限相关名称、15 个来源的请求/定义/组件保护关系及摘要，不包含源路径、原厂代码或认证信息。Android 11 起对已核对参考包使用定向 `<queries>`，已声明四项原生热点候选权限，实际授予仍以当前应用身份检测。

`L7SpecialAccessProbe` 分别查询修改系统设置、悬浮窗、使用情况访问、安装未知应用与所有文件访问；普通授权原值继续保留，特殊访问允许不会被普通查询拒绝覆盖。使用情况访问通过 `OPSTR_GET_USAGE_STATS` 查询，默认模式回退普通授予，不读取使用记录；所有文件访问仅在 API 30 起调用。未声明显示待验证，标准新权限仅在定义不可见且系统版本不足时显示不适用，厂商回移定义仍可查询。查询不自动申请或上传。依据：[Settings.System.canWrite](https://developer.android.com/reference/android/provider/Settings.System#canWrite(android.content.Context))、[AppOpsManager](https://developer.android.com/reference/android/app/AppOpsManager#OPSTR_GET_USAGE_STATS)、[Environment.isExternalStorageManager](https://developer.android.com/reference/android/os/Environment#isExternalStorageManager())。新批次使用 `probeVersion=5`（在 SDK 契约和媒体会话基础上加入候选提供包／组件和 SDK 分支元数据），历史报告不改写。

`L7HotspotProbe` 独立执行 `getWifiApState`、`getSoftApConfiguration` 与兼容 `getWifiApConfiguration`，支持单项复查；Android 10 的新版接口标记不适用。分别保留接口拒绝、不可见、服务不可用、空配置、掩码、无效或有效配置，不以一条失败推断另一条能力。字段仅为存在性、安全类型和有效性，报告不保存热点名称／密码；采集不修改已存配置、不写入或启停热点。四项声明为 `NETWORK_SETTINGS`、`OVERRIDE_WIFI_CONFIG`、`TETHER_PRIVILEGED`、`NETWORK_STACK`，声明与实际授权、调用结果各自记录。

`L7ProbeStore` 原子保存白名单 JSON，每批 2 MiB、10 批和总计 20 MiB 限制；截断有标记，未完成批次在下次读取时标记中断，不续跑。环境摘要用于区分版本、授权与构建变化，不保存原始构建串或硬件唯一编号。

媒体与导航的实现范围为车机 Android 原生服务注册与字段上报；原厂服务负责后续系统内部通讯和显示分发。本应用核对 Android 接入契约、注册生命周期、更新触发与实际显示结果。

`L7ReportingProbe` 保留媒体中心、HUD、系统媒体显示三项专项及单项复查，候选权限与服务授权分开记录。SDK 可见性沿本应用／框架与已安装的精确参考包查询，不执行类静态初始化；`ENV-SDK-CONTRACT` 另核对实际注册重载、回调类型、getter、ICreator 和导航启停／路名签名。`ENV-MEDIA-SESSIONS` 仅记录公开系统查询的会话数量与本应用播放状态，声明 MEDIA_CONTENT_CONTROL 后仍可能遭系统拒绝，拒绝不等于没有会话。采集不调用 SDK get/init/create/register，不发送媒体或导航数据、不请求特殊授权；三项 REPORT 继续保留业务待验证。Android Binder 交易号仅用于核对原生服务接口。 `L7VendorServiceProbe` 沿样本的精确提供包与旧候选服务查询元数据、启用／导出和组件保护；包与组件查询彼此独立，缺失、拒绝和异常分别保留。`EAS_SUPPORT` 缺失、非整数与 0 分开记录，未见不能推断卸载或无服务。查询不绑定或调用厂商 Binder，服务实际准入始终待验。

真实 CarPlay 会话通过 `L7MediaCenterSession` 及 `L7ReflectiveMediaCenter` 使用已安装 SDK，以本应用 Context、UID 和包名注册；不运行原厂 Application、不打包 OEM 实现。MusicClient 是类，使用 DexMaker 生成薄子类并通过公开 [InMemoryDexClassLoader](https://developer.android.com/reference/dalvik/system/InMemoryDexClassLoader) 加载；采用 [DexMaker 的低层生成 API](https://github.com/linkedin/dexmaker/tree/2.28.6)，不使用隐藏 API 信任豁免。 `SdkSubclass.override` 保留约 59 行，原因是必须先集中分配 Dex 局部变量，再发出装箱、回调与返回指令；仅负责薄子类方法生成，加载、会话和上报职责已独立。旧 IMusicClient 注册重载在样本中直接返回 null。当前固件 EAS_SUPPORT=1 时使用 SDK 在线源 6，其余继续使用原厂参考源 13；三参数注册重载可用时关联本应用 MediaSession，不借用其他应用包名。准备一致的曲目／封面快照后再请求播放权；就绪、有效 token、源列表接受、当前对象与显示各自形成证据。首次暂停也可接收标准控制；未知状态不发送猜测的厂商枚举。请求播放按明确播放边沿触发，进度缓存独立，不循环抢源。状态更新失败保留待更新快照，同一快照最多三次；焦点或来源恢复时重新发布。服务重复就绪不重注册，单会话注册最多三次。

曲目、状态、毫秒进度与封面共用同一注册。切歌只提交一份曲目与当前所选 URI 的快照；迟到解码通知重查当前选择。手机清空媒体时删除旧缓存并使未交付结果失效；默认更新仅在传输 ID 不变时保留封面。封面复用采样预算，后台缓存至不可导出的 FileProvider 子目录，最多四张并按传输 ID 关联；SDK Binder getter 按实际调用 UID 所属包授予只读 URI，断开撤权、删除和撤销旧 getter。命令记录本地消费、手机入队、执行与协议写入，蓝牙等待和发送执行前都检查具体原手机会话，即使控制器未替换也拒绝重连后的旧任务；写入不等于手机执行。首次 AirPlay 激活前的媒体快照与最多一份受传输大小限制的封面暂存，实际激活后衔接，不提前伪报播放。跨入口同一命令的去重窗口为 80 ms，同入口连按和相反命令保留；语音条件日志在过滤之前写入。清理顺序先使回调失效，再尝试清源、注销和释放。远端 IPC 阻塞或拒绝的实际清理效果仍需实车验证。

HUD 通过独立 `L7NavigationSession` 复用 iAP2 解析，仅调用地图 Java／Smali 确认的框架创建、交互回调、启停与路名；不复用其他车型输出或修改车辆信号。有效引导才初始化，创建失败本会话只尝试一次；必须确认服务 Binder 存活后才发布，未就绪保留最新路名，服务恢复或存活 Binder 被替换后重发启停与路名。`serviceConnection` 锚点区分首次连接与服务替换，不输出 Binder 标识。字段调用失败不永久禁用，同一路名最多三次尝试；重复字段不重发，过期、取消和断开尝试停止与注销。道路名本地预算为 256 字符，非已确认厂商上限。转向枚举、距离单位、ETA 语义、车道、控制权和 HUD／仪表目标仍需核对 Android 服务契约，未发布猜测字段；调用 RETURNED 与实际显示分别验收。

`L7ProbeTable` 将全部结果放在一张三列表中，行最小 48dp、文字 14sp，状态带图标、颜色和文字；技术全名与完整原因在行详情中查看。`L7ProbeStatus` 区分授权、业务证据及查询失败；未知定义不映射成不支持，特殊访问未授权显示灰色。

`L7ProbeLog` 在采集工作线程写入 `logs/probe-latest.log`，保留 `probe-previous.log`，每份按实际 UTF-8 限制为 512 KiB，独立原子保存，不争用连接日志文件。记录使用短批次号、时间、结果与白名单字段，并继续通过统一脱敏规则；先保留所有检查项结论，再填充详细证据，细节截断有标记，完整证据仍在 JSON 中；权限名和技术字段保留原名，敏感字段只遮盖值，原始协议载荷继续排除。完整 JSON 与日志分别保存，导出与手动上传纳入采集日志；上传预算优先保留采集记录，避免被大量会话日志挤掉。进入页面和收集动作不发网络请求。当前完成基础扫描及日志归并；实车问题复现、Hook 和 USB 主动测试仍按后续批次实施；原生热点一键操作见连接约束，尚待实车验证。

`L7DebugTasks` 由 Activity 持有，首页收集、结果页重新收集/单项复查和两处上传入口复用同一任务窗口。`L7TaskProgressDialog` 区分执行、停止等待、失败重试和结果；200 ms 刷新进度，关闭或后台移除回调。开始操作防重复，普通页面刷新不重启任务；返回/右上角关闭先确认终止，点击外部不关闭。收集停止只停止后续查询并拒收迟到结果，不强杀系统调用；上传关闭当前连接并阻止后续批次。配置重建只重新绑定仍在运行的任务；进入后台停止、销毁释放窗口，回来不自动续传。

悬浮日志使用共用开关行，状态由服务实际显示结果回填；程序回填不会再次触发用户回调。权限引导取消、启动失败保持关闭，关闭浮窗或权限撤销同步更新。

空快照进入 EMPTY 状态，不发送摘要、不写成功历史。HTTP 非成功响应最多读取 4097 字节，只将已知的日志流删除中错误映射为本地化提示，不保存或展示响应原文。

`RemoteLogHistory` 只在完整报告被服务器确认后保存成功时间与条数，不记录地址、认证或设备身份；记录独立于服务器配置，失败、取消和修改配置不覆盖。两处上传入口读取同一摘要，执行进度与失败原因留在任务弹窗；重启后仍显示上次成功信息，不补造旧版记录。

清空操作复用采集工作线程并与采集互斥；运行日志写入使用代次检查，清空后旧队列不能回填。两种清空都取消上传并丢弃旧重试快照，清空期间禁止新上传。清空报告限定本地报告文件及其原子写入副本，保留运行日志和用户导出。LogView 读取、筛选和复制不触发上传，关闭时释放线程与快照。旧版本已过滤掉的内容无法补回，新记录才适用当前脱敏规则。

### OpenObserve 打包默认值

将根目录 [.env.example](../.env.example) 复制为 `.env`，设置 `L7_LOG_SERVER_URL` 和 `L7_LOG_AUTHORIZATION`。URL 支持 `/api/组织/{HeadUnit}-{DeviceID}/_json` 或 `/api/组织/{DeviceID}/_json`，占位符只允许位于流名位置；也兼容控制台普通示例。实际上传保留服务器、代理前缀与组织，再替换流名；花括号原样保存到打包资源，不执行 shell 插值。认证值为完整的 `Basic <Base64(用户名:写入凭据)>`，使用具有目标设备日志流写入权限的凭据。显式环境变量优先，Docker 构建支持。配置只提供默认值，不触发上传。内置地址通过 RemoteLogEditor 与展示分离，列表仅显示 `*****`，弹窗不向可复制的输入文本填入内置地址或已有认证。空字段解析为保留原值；未修改不保存覆盖值，避免冻结后续打包默认值。更换地址不得自动复用原认证。

协议使用 OpenObserve 官方 [JSON 批量写入接口](https://openobserve.ai/docs/reference/api/ingestion/logs/json/) 和 [Basic 认证](https://openobserve.ai/docs/reference/api/)。每条日志一个事件，一次手动任务按 UTF-8 JSON 实际字节限制为 1 MiB，每批最多 256 KiB / 1000 条；最多保留 5000 条日志另加整理摘要。按八份运行日志、内存和两份采集日志顺序收集，预算不足先移除较旧运行记录；不按文本去重，保留重复故障证据。`source` 标明来源，`batch_index/batch_count` 标明批次，整理摘要记录省略、遮盖、原始载荷排除、行截断和文件尾部裁剪数量。每行最多 4096 字符，超限附加标记。`report_id` 与 `event_id` 在手动重试时保持不变，但不承诺服务端自动去重。每批只有响应目标流的 `successful` 等于发送数量且 `failed=0` 才推进；部分拒收立即停止并报错，手动重试从未确认批次继续，全部批次完成才显示成功。请求不跟随重定向，不打印认证值或响应正文。

`HeadUnit` 取与诊断中 Head unit 相同的 `Build.MANUFACTURER` 和 `Build.MODEL`，转为小写安全字符并限制长度；缺失时使用 `head_unit`。`DeviceID` 优先基于 Android ID，不可用时尝试标准序列号 API，仍不可用则生成本地随机值；通过带包名、用途版本及来源类型的 SHA-256 生成 20 位十六进制哈希，分四组显示。旧编号或型号变化保留已有哈希，仅更新型号前缀。只持久化名称与哈希结果，与服务器配置分开保存；不读取 VIN、MAC 或 IMEI，不保存原始唯一标识。名称仅用于请求 URL 的流名位置，JSON 记录不包含 `device_id`；按 OpenObserve 的规范化流名验证回执并显示名称。它用于日志关联，不作为授权或身份验证依据；正常覆盖升级及重试不改变哈希，恢复出厂、更换签名、用户或随机回退后清除数据可能改变哈希。

上传工作线程不持有 Activity，不占音视频线程；退出、撤回或配置变化取消任务，迟到结果按代次隔离。没有自动采集服务、定时上传或自建日志后台。APK 默认凭据可被提取，应限制写入权限并按测试批次轮换；根目录 `.env` 和真实服务地址不进入公开文档或 Git。

### 认证与签名

默认认证输入为 `.private/auth-assets/offline-mfi/identity.pk8` 与 `certificate.p7b`，Git 忽略。可通过 `DIPLAY_AUTH_ASSETS_DIR=/absolute/path/to/runtime-assets` 指定替代目录；仅运行时只读挂载到 `/run/l7-auth`，不写入镜像。材料不随源码分发，交付包与输入的一致性在本地检查。

发布通过本机安全方式设置 `ANDROID_KEYSTORE_PATH`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`，运行 `bash scripts/build-android-docker.sh --release`。入口执行 `:mobile:assembleStandaloneRelease`，输出 `mobile/build/outputs/apk/release/mobile-release.apk`；keystore 只读挂载，缺参数即停止，发布同样使用一次性容器。

Android 签名与 MFi 认证分别管理；同包名或公开证书不赋予原厂身份和系统权限。用容器内 `apksigner verify --print-certs` 检查产物，安装前核对签名与版本码。凭据与报告规则见 [SECURITY.md](../SECURITY.md)。

### AVD 屏幕与密度校准

预览使用仓库外 `tools/scripts/preview-l7.sh`，仅预览依赖该工具箱；`--restart-preview` 显式重启，正常构建复用实例。构建失败不安装旧产物。

AVD 为 Android 11、1440×1920 竖屏、系统逻辑密度 320、字体缩放 1.0；320 是预览档，非实车密度。应用 UI 默认中档 280，与系统密度分开。面板约 181.82 PPI 不能推导 Android 逻辑 DPI。

```bash
# 配置已开机的专用 AVD；仅操作匹配名称与 API 的模拟器。
python3 scripts/configure-l7-avd.py

bash scripts/build-l7-host.sh --preview --density 240
```

模拟器不能代表 8155 编解码、Flyme 权限、OEM 窗口、音频 BUS、蓝牙交接及真实 CarPlay。配置结果与截图仅放忽略目录，未经实车确认的预览参数不写成车辆事实。

开发检查至少连续运行 30 分钟、重连 10 次；发布验收至少 60 分钟、重连 20 次。分别记录首帧、排队、呈现、触控、CPU/PSS 和温度；匿名结论不携带车辆/手机标识、固件构建串或原始日志名。工程目标为媒体建立后首帧 P95 ≤2 秒、排队 P95 ≤100 ms、接收至呈现 P95 ≤150 ms、本机操作反馈 ≤100 ms，均需实测，代理指标不冒充物理测量。
