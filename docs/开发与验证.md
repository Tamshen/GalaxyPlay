[项目入口](../README.md) · [使用说明](使用说明.md) · [测试运行](../e2e/README.md)

## 范围与模块

仅面向吉利银河 L7（2023 / 2024 款目标配置）、8155、Flyme OS / Android 11，最低 Android 10。屏幕规格为 13.2 英寸、1440×1920、3:4；运行窗口、密度、权限与硬件能力均运行时获取，不能由年款推定。每种固件单独验收。

| 模块 | 职责 |
| --- | --- |
| `shared` | DiPlay 协议、传输、认证和媒体核心 |
| `common` | 宿主、设置、原生组件与 L7 接入 |
| `mobile` | L7CarPlay APK 入口，包名 `com.ecarx.carplay` |
| `e2e` | 单元、组件、设备场景及交付检查 |

应用版本与 DiPlay 核心基线唯一维护于 [版本配置](../gradle/l7-version.properties)。核心是仓库内源码模块，不依赖工作区旁边的 DiPlay 目录。保留上游署名与许可，不启用其他车型入口、HUD 或车辆控制。

UI 设计与离线示例维护于工作区 `FlymeAutoOS/UI/l7carplay/组件示例.html`，完整契约为同目录 `界面规范.md`。产品仓库保留 Android 原生组件和测试，HTML 不进入 APK、构建依赖或站点发布。组件职责见 [AGENTS.md](../AGENTS.md)。

## 运行约束

- 会话控制器、视频 worker、音频模块分别持有连接、MediaCodec、AudioTrack/AudioRecord；回调校验会话代次，退出幂等释放，不在 UI 线程等待资源退出。
- 无线采用用户开启的车机原生热点与 MANUAL 接入；不改热点、不静默切换 P2P 或 LocalOnlyHotspot。有线连接与认证后端分别验收。
- 首次协议、USB、自动连接和服务入口统一检查同意状态；协议正文唯一维护于 `common/src/main/assets/l7-first-use-agreement.md`。
- 进入设置、改变 UI 密度或昼夜主题只刷新控件，不停止会话或重建视频 Surface；撤回协议与退出清理全部服务和悬浮窗。
- 面板规格换算约为 201×268 mm；按视频区域占真实显示像素的比例上报物理区域，不用 UI DPI 或编码档位虚增毫米值。此数值属于规格换算，非实物测量。
- 临时缩窗及恢复到启动窗口以内保持原连接画布；真正旋转、系统栏设置变化或超出启动窗口才重连。重建前等待窗口稳定并重查权限，触控继续使用同一等比矩形。
- 视频矩形、crop、旋转和触控采用同一变换；按实际窗口、Insets、density、fontScale 布局，等比显示允许黑边，零窗口不协商，避让区域不重复计入 safeArea。

USB 连接不要求热点配置；VPN 仅接管本应用，添加应用失败不回退到全局 VPN。AirPlay 首选端口被占用时尝试 7001～7010，再由系统分配临时端口；Bonjour 与 iAP2 使用实际端口。无线蓝牙只承担认证和 Wi-Fi 引导，定位由运行隧道自行订阅，缺少 GPS 方向时不伪造朝北。

诊断写入使用一个后台线程、最多 64 条待写记录，拥塞时淘汰最旧记录。记录连接阶段、接口及接收计数、慢读取、资源关闭耗时和麦克风读写计数，不记录协议或语音载荷。Android 11 导出最多三条本应用进程退出原因与内存数值，不读取系统堆栈或描述；内核 UDP 计数属于整机，不能视作 CarPlay 独立丢包率。

### 视频与恢复

默认单路 H.264 硬解、30 fps，压缩队列 → MediaCodec → Surface。筛选 MIME、profile、尺寸方向、对齐、帧率和实际初始化结果；HEVC、60 fps 及高分辨率需单独验收。保持有界队列，不增加常态转码、逐帧 Bitmap/JPEG 或像素回读。

| 项目 | 约束 |
| --- | --- |
| 队列 | 60 帧 / 8 MiB 硬上限，接收、排队、输入等待共用 250 ms 帧龄预算 |
| 参考帧 | 丢失后重同步并等待关键帧，请求频率不超过每秒一次 |
| HEVC | hvcC / Annex B 转为 csd-0，缺 VPS/SPS/PPS 拒绝配置；至少三帧输入后，八秒无输出或呈现分别诊断 |
| 恢复 | 连续失败最多四次，250/500/1000 ms 退避；稳定输出十秒或显式新目标重置预算 |
| Surface | 所有 worker 异步解除旧目标后再释放；旧回调不能提交到新目标 |
| 统计 | 接收、输入、提交、呈现回调分开；提交和回调均不等于物理面板测量 |

HEVC 失败提示选择 H.264 后重连，不静默更换解码 MIME。后续降帧率、降画布必须通过重协商或重连生效，本地缩放不等于手机负载降低。

### 音频与按键

| 用途 | 默认策略与候选 |
| --- | --- |
| 媒体 | MEDIA；系统路由 |
| 导航 | ASSISTANCE_NAVIGATION_GUIDANCE；系统路由 |
| Siri | ASSISTANT / VOICE_RECOGNITION；输入输出均交给系统 |
| 电话 | VOICE_COMMUNICATION；系统选择输入输出 |

BUS 默认关闭，保持原版音频路径且不调用 setPreferredDevice；实际路由监听仍保留。显式开启后，媒体候选 BUS00_MEDIA、Siri 输入候选 BUS20_CARPLAY_SIRI_UL、电话按实际带宽匹配，按地址、方向、格式与唯一性枚举，缺失或拒绝回退系统。默认不绑定 BUS01_SYS_NOTIFICATION，不硬编码 deviceId，不混用标准 usage、厂商焦点编号与其他协议参数，不调用未经 L7 验证的 duck/unDuck、HAL 或音量组接口。偏好请求成功与实际 routed device 分别记录。

三用途设置只覆盖输出策略，协议角色独立；legacy 策略不叠加 BUS。音频默认值与焦点行为对齐 DiPlay 原版 0.2.11：焦点默认关闭，导航不参与焦点申请或本地降音；开启焦点时，媒体请求 GAIN、电话请求 TRANSIENT、Siri 请求 MAY_DUCK。多流共用请求，按原版媒体 > 电话 > Siri 顺序选择；只有系统 CAN_DUCK 回调将受管音轨降至 0.2，GAIN 恢复，LOSS/TRANSIENT 或请求拒绝不强制静音。电话与导航的实际混音由手机和系统策略协调，必须实车验证。保留会话关闭与旧回调隔离；明确播放可以重试媒体焦点，回调不循环抢焦点。

旧安装保留手动输出选择与焦点开关；“恢复原版默认音频”一次恢复三用途为 0、焦点关闭、BUS 关闭、高级映射关闭、缓冲 300 ms、通话音效开启，下次连接生效，其他配置不变。音频协商表、分类及 Opus 编码与原版一致；补齐解码阶段、输出格式与计数诊断，移除音频载荷片段日志。

通话默认尝试系统 AEC/NS，可在音频设置关闭，下次连接生效；输入默认交给系统，BUS 仅按显式开关启用。仅普通模式可临时进入 MODE_IN_COMMUNICATION，不覆盖原车通话、响铃或其他通信来源；最后一条通话录音停止后，仅当模式仍为本模块设置值时恢复。音效不可用、模式设置被拒绝或诊断失败不阻断录音，Siri 保持原录音路径。Android 公共 API 不能区分其他应用重新写入相同模式的情况，实车需验证与蓝牙通话共存。

歌曲信息保留 iAP2 增量字段，首次暂停必须发布。系统 MediaSession 只在歌曲/封面变化时更新元数据，进度不重复传送图片，也不额外申请音频焦点。封面单份最多 2 MiB，传输及解码队列各最多四份，解码尺寸限制为 384 像素，旧会话回调丢弃；不新增常态视频像素回读。

蓝牙互斥只针对本次已确认手机的 A2DP，保留 HFP、配对和其他设备。隐藏接口按权限和真实结果降级；查询最多六秒，断开确认最多三秒，每会话至多两次。等待只保留最后一次明确播放，暂停取消待发命令，超时恢复手动路径，不因断开完成自动播放。USB 未确认目标时不自动断开。

方向盘标准媒体键使用 MediaSession；语音广播 `action_steering_wheel_controller_event` 的 type 3/4 按长短按处理，仅转发真实 CarPlay 会话，短按按助手状态处理，300 ms 内去重；不直接映射广播 1/2。厂商按键和焦点仍需实车验证。

麦克风只在 Siri / 通话需要时采集，结束释放；只统计状态和能量摘要，不保存人声。Opus 48 kHz 路径需核对协商格式；成功读取或有能量不能证明手机收到可识别语音。

## Docker 构建

使用 `mobiledevops/android-sdk-image:latest` 和仓库 Gradle Wrapper，编译、测试、lint、打包均在 Docker 中执行。先启动 OrbStack 或 Docker Desktop，在仓库根目录运行：

```bash
# Apple Silicon 默认 ARM64 常驻开发容器，仅打包。
bash scripts/build-l7-host.sh
# 构建成功后复用 AVD、覆盖安装并打开。
bash scripts/build-l7-host.sh --preview
# 完整单测、mobile lint、内置认证 APK；默认 amd64。
bash scripts/build-l7-host.sh --check
# 无本地认证时显式生成源码验证包。
bash scripts/build-android-docker.sh --source-only
# 自定义任务，筛选方法见 e2e/README.md。
bash scripts/build-android-docker.sh -- :common:testDebugUnitTest
```

默认执行 `:mobile:assembleStandaloneDebug`，缺认证输入即停止；源码验证包执行 `:mobile:assembleDebug`，安装后需配置认证。调试输出 `mobile/build/outputs/apk/debug/mobile-debug.apk`。普通自定义任务不默认挂载认证，指定 standalone 任务或认证环境变量时才挂载。

工具链由 [Dockerfile](../docker/Dockerfile) 和 [ARM64 Dockerfile](../docker/Dockerfile.arm64) 管理：SDK 37、Build Tools 36.0.0、NDK 28.2.13676358、JDK 25。ARM64 调试为原生 Java/Gradle 加 x86 SDK 工具的混合路径，容器架构与 APK 的 `arm64-v8a` ABI 分开。`latest` 不代表固定镜像，实际摘要保存到本地构建记录。

`--amd64` 可切回完整检查路径；底层快速打包为 `bash scripts/build-android-docker.sh --arm64 --warm --standalone`，架构参数放在模式或自定义任务前。不要例行 clean、删除缓存或重启容器。不混入 macOS SDK/NDK/JDK，入口拒绝本机 `local.properties` 路径；不并发写构建输出。

| 位置 | 用途 |
| --- | --- |
| `docker/` | 镜像构建上下文，不含源码与认证 |
| `l7carplay-gradle-amd64` / `l7carplay-gradle-arm64` 卷 | 分架构工具链和 Gradle 缓存 |
| `l7carplay-debug-signing` 卷 | 持久化调试签名，删除后可能无法覆盖安装 |
| `build/host-logs/` | 忽略 Git 的本地构建记录 |

### 认证与签名

默认认证输入为 `.private/auth-assets/offline-mfi/identity.pk8` 与 `certificate.p7b`，Git 忽略。可通过 `DIPLAY_AUTH_ASSETS_DIR=/absolute/path/to/runtime-assets` 指定替代目录；仅运行时只读挂载到 `/run/l7-auth`，不写入镜像。材料不随源码分发，交付包与输入的一致性在本地检查。

发布通过本机安全方式设置 `ANDROID_KEYSTORE_PATH`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`，运行 `bash scripts/build-android-docker.sh --release`。入口执行 `:mobile:assembleStandaloneRelease`，输出 `mobile/build/outputs/apk/release/mobile-release.apk`；keystore 只读挂载，缺参数即停止，发布不使用 `--warm`。

Android 签名与 MFi 认证分别管理；同包名或公开证书不赋予原厂身份和系统权限。用容器内 `apksigner verify --print-certs` 检查产物，安装前核对签名与版本码。凭据与报告规则见 [SECURITY.md](../SECURITY.md)。

### AVD 屏幕与密度校准

预览使用仓库外 `tools/scripts/preview-l7.sh`，仅预览依赖该工具箱；`--restart-preview` 显式重启，正常构建复用实例。构建失败不安装旧产物。

AVD 为 Android 11、1440×1920 竖屏、系统逻辑密度 320、字体缩放 1.0；320 是预览档，非实车密度。应用 UI 默认中档 280，与系统密度分开。面板约 181.82 PPI 不能推导 Android 逻辑 DPI。

```bash
# 配置已开机的专用 AVD；仅操作匹配名称与 API 的模拟器。
python3 scripts/configure-l7-avd.py
# 只读检查。
python3 scripts/configure-l7-avd.py --check
# 已确认实车密度时指定预览值；240 仅示例。
bash scripts/build-l7-host.sh --preview --density 240
```

模拟器不能代表 8155 编解码、Flyme 权限、OEM 窗口、音频 BUS、蓝牙交接及真实 CarPlay。配置结果与截图仅放忽略目录，未经实车确认的预览参数不写成车辆事实。

### 实车反馈与参考迁移准备

2026-10-04 收到实测反馈：carlito12345 的 DiPlay 二改蓝牙媒体交接可实时生效；方控播放 / 暂停无效、导航无声、进入设置后疑似画面缩小均发生在 **L7CarPlay**。测试 APK 的版本与提交尚未核对，不能直接认定为当前 `0.1.25` 构建的复现结果，也不能把参考项目的蓝牙效果视作其余能力已在 L7 通过。

对照源码为 L7 `a1ed7a3` 与参考项目 `0109cf7`（0.2.11），原版 DiPlay 0.2.11（76a9ca9）已获用户确认语音正常，本轮据此对齐音频默认值、焦点及系统路由，并补齐音频诊断；实车效果仍待验。其余问题继续按表逐项处理。参考项目及许可见[来源说明](第三方许可.md#diplay-geely-reference)。

发布前固定 APK 与配置，在停车状态验收：安装与协议、无线/USB 首帧和重连、触控/画幅/窗口变化、三用途声音与通话、蓝牙焦点竞争、倒车临时占屏、休眠唤醒、撤回/退出释放、权限拒绝和故障恢复。各认证后端分别验收；HEVC 和高帧率单独测试。

开发检查至少连续运行 30 分钟、重连 10 次；发布验收至少 60 分钟、重连 20 次。分别记录首帧、排队、呈现、触控、CPU/PSS 和温度；匿名结论不携带车辆/手机标识、固件构建串或原始日志名。工程目标为媒体建立后首帧 P95 ≤2 秒、排队 P95 ≤100 ms、接收至呈现 P95 ≤150 ms、本机操作反馈 ≤100 ms，均需实测，代理指标不冒充物理测量。

## 上游维护

`origin` 为 Tamshen/L7CarPlay，`upstream` 为 shihabal3amri/DiPlay。以当前源码快照为主线；上游在独立临时检出中审查，按已记录核心基线提取必要补丁，在本仓库形成独立提交，不将上游完整提交图重新并入发布分支。核对连接默认值、资源所有权、测试迁移、包名、许可和认证资产；产品版本独立递增，核心基线仅在实际同步后更新。

本次精选补丁来源更新至原版 DiPlay 0.2.11 `76a9ca9`；核心快照基线仍为 0.2.8，关于页显示 `0.2.8+patch.0.2.11`。此前的 USBMUX、应用级 VPN、端口回退、窗口保活、定位订阅、连接诊断、歌曲封面与通话音效继续保留；本轮对齐原版音频默认值、焦点与系统路由，并提取音频诊断补充。L7 的界面、MANUAL 热点、认证后端、显示生命周期与有界视频队列保持适配，未引入上游其他车型、自动热点、TV、站点、多语言或 Android 9 专用兼容。
