## 范围与模块

仅面向吉利银河 L7（2023 / 2024 款目标配置）、8155、Flyme OS / Android 11，最低 Android 10。屏幕规格为 13.2 英寸、1440×1920、3:4；运行窗口、密度、权限与硬件能力均运行时获取，不能由年款推定。每种固件单独验收。

| 模块 | 职责 |
| --- | --- |
| `shared` | DiPlay 协议、传输、认证和媒体核心 |
| `common` | 宿主、设置、原生组件与 L7 接入 |
| `mobile` | L7CarPlay APK 入口，包名 `com.ecarx.carplay` |
| `e2e` | 单元、组件、设备场景及交付检查 |

应用版本与 DiPlay 核心基线唯一维护于 [版本配置](../gradle/l7-version.properties)。核心是仓库内源码模块，不依赖工作区旁边的 DiPlay 目录。保留上游署名与许可，不启用其他车型入口、HUD 或车辆控制。

UI 设计与离线示例维护于工作区 `FlymeAutoOS/UI/l7carplay/组件示例.html`，完整契约为同目录 `界面规范.md`。产品仓库保留 Android 原生组件和测试，HTML 不进入 APK、构建依赖或站点发布。组件职责见 [AGENTS.md](../AGENTS.md)。

## 运行约束

- 会话控制器、视频 worker、音频模块分别持有连接、MediaCodec、AudioTrack/AudioRecord；回调校验会话代次，退出幂等释放，不在 UI 线程等待资源退出。
- 无线采用 Android 原生热点与 MANUAL 接入，区别于车机桌面热点。连接设置自动尝试读取配置，用户可主动开启或应用生成配置；开启中的热点不重配，退出不关热点。不静默切换 P2P 或 LocalOnlyHotspot，有线连接与认证分别验收。
- 首次协议、USB、自动连接和服务入口统一检查同意状态；协议正文唯一维护于 `common/src/main/assets/l7-first-use-agreement.md`。
- 进入设置、改变 UI 密度或昼夜主题只刷新控件，不停止会话或重建视频 Surface；撤回协议与退出清理全部服务和悬浮窗。
- 面板规格换算约为 201×268 mm；按视频区域占真实显示像素的比例上报物理区域，不用 UI DPI 或编码档位虚增毫米值。此数值属于规格换算，非实物测量。
- 临时缩窗及恢复到启动窗口以内保持原连接画布；真正旋转、系统栏设置变化或超出启动窗口才重连。重建前等待窗口稳定并重查权限，触控继续使用同一等比矩形。
- 视频矩形、crop、旋转和触控采用同一变换；按实际窗口、Insets、density、fontScale 布局，等比显示允许黑边，零窗口不协商，避让区域不重复计入 safeArea。

自动连接启用时，Application 在 Activity 构造前同步写入启动标记。连续 3 次未完成启动或连接即关闭自动连接；Java 异常保存类型与最多 8 个本项目栈帧，Android 11 结合本进程退出记录识别 native/ANR，已知主动停止与系统回收不累计。Android 10 或退出信息缺失时按未完成标记保守恢复。首页前台无会话或当前连接连续稳定 30 秒后复位；主动取消、退出复位。保护状态拦截任务恢复与 USB 直接拉起，用户可从首页手动连接，明确重新开启自动连接才解除保护，不清除配置或认证。

USB 连接不要求热点配置；VPN 仅接管本应用，添加应用失败不回退到全局 VPN。AirPlay 首选端口被占用时尝试 7001～7010，再由系统分配临时端口；Bonjour 与 iAP2 使用实际端口。无线蓝牙只承担认证和 Wi-Fi 引导，定位由运行隧道自行订阅，缺少 GPS 方向时不伪造朝北。

诊断写入使用一个后台线程、最多 64 条待写记录，拥塞时淘汰最旧记录。记录连接阶段、接口及接收计数、慢读取、资源关闭耗时和麦克风读写计数，不记录协议或语音载荷。Android 11 导出最多三条本应用进程退出原因与内存数值，不读取系统堆栈或描述；内核 UDP 计数属于整机，不能视作 CarPlay 独立丢包率。

### 视频与恢复

默认单路 H.264 硬解、30 fps，压缩队列 → MediaCodec → Surface。筛选 MIME、profile、尺寸方向、对齐、帧率和实际初始化结果；HEVC、60 fps 及高分辨率需单独验收。保持有界队列，不增加常态转码、逐帧 Bitmap/JPEG 或像素回读。

| 项目 | 约束 |
| --- | --- |
| 队列 | 60 帧 / 8 MiB 硬上限，接收、排队、输入等待共用 250 ms 帧龄预算 |
| 参考帧 | 丢失后重同步并等待关键帧，请求频率不超过每秒一次 |
| HEVC | hvcC / Annex B 转为 csd-0，缺 VPS/SPS/PPS 拒绝配置；至少三帧输入后，八秒无输出或呈现分别诊断 |
| 恢复 | 连续失败最多四次，250/500/1000 ms 退避；稳定输出十秒或显式新目标重置预算 |
| Surface | 所有 worker 异步解除旧目标后再释放；旧回调不能提交到新目标 |
| 统计 | 接收、输入、提交、呈现回调分开；提交和回调均不等于物理面板测量 |

HEVC 失败提示选择 H.264 后重连，不静默更换解码 MIME。后续降帧率、降画布必须通过重协商或重连生效，本地缩放不等于手机负载降低。

### 音频与按键

| 用途 | 默认策略与候选 |
| --- | --- |
| 媒体 | MEDIA；系统路由 |
| 导航 | ASSISTANCE_NAVIGATION_GUIDANCE；系统路由 |
| Siri | ASSISTANT / VOICE_RECOGNITION；输入输出均交给系统 |
| 电话 | VOICE_COMMUNICATION；系统选择输入输出 |

BUS 默认关闭，保持系统设备选择且不调用 setPreferredDevice；实际路由监听仍保留。显式开启后，媒体候选 BUS00_MEDIA、Siri 输入候选 BUS20_CARPLAY_SIRI_UL、电话按实际带宽匹配，按地址、方向、格式与唯一性枚举，缺失或拒绝回退系统。默认不绑定 BUS01_SYS_NOTIFICATION，不硬编码 deviceId，不混用标准 usage、厂商焦点编号与其他协议参数，不调用未经 L7 验证的 duck/unDuck、HAL 或音量组接口。偏好请求成功与实际 routed device 分别记录。

三用途设置只覆盖输出策略，协议角色独立；legacy 策略不叠加 BUS。音频配置与焦点处理参考博越 DiPlay v0.2.11：媒体 / Siri 自动用途、导航 legacy stream 14、焦点及高级映射默认开启。电话 > Siri / 铃声 > 导航 > 媒体；媒体申请 GAIN，其余申请 TRANSIENT，导航把媒体降至 0.2，其他优先流抑制低优先流。系统 CAN_DUCK 叠乘降音、GAIN 恢复；永久 LOSS 抑制媒体，明确播放才允许恢复请求，不在失焦回调内抢焦点。会话关闭和旧监听器继续隔离。

框架 `AUDIO_USAGE_CP_*` 优先，其次 `/vendor/etc/carplay/carplay_config.json` 的 `AudioAttrs`，最后标准 Android 用途；读取最多 64 KiB，只保留音频段，不记录正文。忽略把非媒体全部映射为 MEDIA 的模板。Siri / 电话输入按有线、无线和带宽查找 `AUDIO_SOURCE_*`，拒绝或录音启动失败释放后回退标准源。试听共用配置、流拒绝回退和焦点，设备是否真正发声仍需实车确认。

升级首次应用博越配置，覆盖旧音频实验值，此后保留手动调整；“恢复博越默认音频”可再次应用。BUS 默认关闭、缓冲 300 ms、通话音效开启，其他配置不变。协议协商和编解码仍用官方核心基线，不移入 KX11 / Android 9 专属分支。

通话默认尝试系统 AEC/NS，可在音频设置关闭，下次连接生效；输入默认交给系统，BUS 仅按显式开关启用。仅普通模式可临时进入 MODE_IN_COMMUNICATION，不覆盖原车通话、响铃或其他通信来源；最后一条通话录音停止后，仅当模式仍为本模块设置值时恢复。音效不可用、模式设置被拒绝或诊断失败不阻断录音，Siri 保持原录音路径。Android 公共 API 不能区分其他应用重新写入相同模式的情况，实车需验证与蓝牙通话共存。

歌曲信息保留 iAP2 增量字段，首次暂停必须发布。系统 MediaSession 只在歌曲/封面变化时更新元数据，进度不重复传送图片，也不额外申请音频焦点。封面单份最多 2 MiB，传输及解码队列各最多四份，解码尺寸限制为 384 像素，旧会话回调丢弃；不新增常态视频像素回读。

蓝牙互斥只针对本次已确认手机的 A2DP，保留 HFP、配对和其他设备。隐藏接口按权限和真实结果降级；查询最多六秒，断开确认最多三秒，每会话至多两次。等待只保留最后一次明确播放，暂停取消待发命令，超时恢复手动路径，不因断开完成自动播放。USB 未确认目标时不自动断开。

方向盘标准媒体键使用 MediaSession；语音广播 `action_steering_wheel_controller_event` 的 type 3/4 按长短按处理，仅转发真实 CarPlay 会话，短按按助手状态处理，300 ms 内去重；不直接映射广播 1/2。厂商按键和焦点仍需实车验证。

麦克风只在 Siri / 通话需要时采集，结束释放；只统计状态和能量摘要，不保存人声。Opus 48 kHz 路径需核对协商格式；成功读取或有能量不能证明手机收到可识别语音。

## Docker 构建

使用 `mobiledevops/android-sdk-image:latest` 和仓库 Gradle Wrapper，编译、测试、lint、打包均在 Docker 中执行。先启动 OrbStack 或 Docker Desktop，在仓库根目录运行：

```bash
# Apple Silicon 默认 ARM64 一次性容器，仅打包。
bash scripts/build-l7-host.sh
# 构建成功后复用 AVD、覆盖安装并打开。
bash scripts/build-l7-host.sh --preview
# 完整单测、mobile lint、内置认证 APK；默认 amd64。
bash scripts/build-l7-host.sh --check
# 无本地认证时显式生成源码验证包。
bash scripts/build-android-docker.sh --source-only
# 自定义任务，筛选方法见 e2e/README.md。
bash scripts/build-android-docker.sh -- :common:testDebugUnitTest
```

默认执行 `:mobile:assembleStandaloneDebug`，缺认证输入即停止；源码验证包执行 `:mobile:assembleDebug`，安装后需配置认证。调试输出 `mobile/build/outputs/apk/debug/mobile-debug.apk`。普通自定义任务不默认挂载认证，指定 standalone 任务或认证环境变量时才挂载。

工具链由 [Dockerfile](../docker/Dockerfile) 和 [ARM64 Dockerfile](../docker/Dockerfile.arm64) 管理：SDK 37、Build Tools 36.0.0、NDK 28.2.13676358、JDK 25。ARM64 调试为原生 Java/Gradle 加 x86 SDK 工具的混合路径，容器架构与 APK 的 `arm64-v8a` ABI 分开。`latest` 不代表固定镜像，实际摘要保存到本地构建记录。

`--amd64` 可切回完整检查路径；底层快速打包为 `bash scripts/build-android-docker.sh --arm64 --standalone`，架构参数放在模式或自定义任务前。构建容器成功、失败或中断后自动停止并删除（`--rm` 加本次 CID 退出清理），不保留 Gradle 常驻进程；旧 `--warm` 参数仅兼容调用。SDK 镜像、Gradle 磁盘缓存和签名卷保留，不例行 clean 或删除缓存。不混入 macOS SDK/NDK/JDK，入口拒绝本机 `local.properties` 路径；不并发写构建输出。

| 位置 | 用途 |
| --- | --- |
| `docker/` | 镜像构建上下文，不含源码与认证 |
| `l7carplay-gradle-amd64` / `l7carplay-gradle-arm64` 卷 | 分架构工具链和 Gradle 缓存 |
| `l7carplay-debug-signing` 卷 | 持久化调试签名，删除后可能无法覆盖安装 |
| `build/host-logs/` | 忽略 Git 的本地构建记录 |

### 原生热点接入

`NativeHotspotConfiguration` 隔离 Android 10 的 WifiConfiguration 和 Android 11 的 SoftApConfiguration；读取失败或密码被掩码时不覆盖已保存值，识别 OPEN/WPA2/WPA3 安全类型。`L7WirelessHotspotGate` 在无线连接入口等待准备结果，成功才继续建链，缺权限或接口不可用时提供原生设置与手动配置；USB 不经过该预检。`L7HotspotTask` 单线程串行执行、按代次丢弃旧结果，系统明确接受后才原子保存名称、密码与安全类型。开启使用 Android 11 TetheringManager 回调，Android 10 保留旧启动路径；回调成功后仍等待真实 AP 开启状态，最多 15 秒。CarPlay 后续通过既有 ManualHotspotManager 等待接口地址，不把热点开启当作投屏连接成功。

`L7WirelessPrerequisites` 在无线页顶部和连接前检查蓝牙开关、读取权限与已选择设备的配对有效性；不要求 A2DP 媒体连接。有线走 USB iAP2，不经过蓝牙门槛。

`settings-connection` 仅承载方式选择；无线和 USB 分别使用独立子路由与三步引导，返回到方式选择。`L7HotspotActions` 由 Activity 持有，复用统一任务弹窗，读取/开启/写入的失败持续显示并提供恢复入口，配置接受与 AP 开启分别记录；后台停止等待，普通页面重绘保留窗口。`L7WiredSettings` 在工作线程只读 USB 枚举与权限，进入页面不发送指令、不申请权限；开始连接前重检，设备缺失需明确确认才进入等待，不支持或查询失败不会启动会话，后台和销毁按代次丢弃迟到结果。既有核心仍负责 USB 权限和设备重枚举。

Android 11 的开启路径接受 WRITE_SETTINGS 或系统级共享权限，而读写 SoftApConfiguration 涉及 NETWORK_SETTINGS；普通修改系统设置授权不能替代。只按应用自身身份调用，系统拒绝或隐藏接口不可用时返回手动配置。保留独立 ACTION_WIFI_SETTINGS 入口且不限定处理包名，允许 Flyme 设置接管；Wi-Fi action 不可用时回退 ACTION_WIRELESS_SETTINGS。原生热点直达失败提供 Wi-Fi 恢复按钮；读取失败保留已存凭据，不能推断 AP 关闭或写入不支持。依据：[AOSP TetheringManager](https://android.googlesource.com/platform/prebuilts/fullsdk/sources/android-30/+/refs/heads/androidx-main-release/android/net/TetheringManager.java)、[Android 11 系统 API](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android11-release/api/system-current.txt)。模拟器不能代替 L7 固件的接口权限与无线建链验证。

### 应用内基础调试

入口为设置 → 调试与日志，顶部按查看、上传、清空日志、清空报告排列四个满宽按钮，复用唯一上传任务；L7LogView 在后台读取快照，以虚拟列表显示，支持搜索高亮和分段复制，打开页面不上传；旧 `settings-diagnostics` / `diagnostics` 路由统一转到 `settings-debug`。日志页使用 `settings-debug-logs`，结果和历史分别使用 `settings-debug-results` / `settings-debug-history`。Header 与系统返回共用路由父级，侧栏仍归设置。新增采集、存储、导出和界面由独立组件管理；既有 DiPlayActivity 为 1851 行，仍超过职责规范；日志查看已移至独立组件，保留既有连接/渲染逻辑以控制改动范围。

`L7ProbeRunner` 使用一个后台工作线程，15 秒总预算；取消或超时后拒收迟到结果，等待尚未返回的查询释放后才允许再运行。基础检查只读取当前应用及可见系统状态，不启动厂商服务、授权、测试输入或认证网络。`L7PermissionProbe` 按原名查询权限，分别保留定义可见性、声明、授权、AppOps 及未验证的有效调用；未知值为 null 加原因，获授只记观察证据。候选目录包含 138 个权限相关名称及来源关系/摘要，不包含源路径、原厂代码或认证信息。

`L7ProbeStore` 原子保存白名单 JSON，每批 2 MiB、10 批和总计 20 MiB 限制；截断有标记，未完成批次在下次读取时标记中断，不续跑。环境摘要用于区分版本、授权与构建变化，不保存原始构建串或硬件唯一编号。

`L7ProbeTable` 将全部结果放在一张三列表中，行最小 48dp、文字 14sp，状态带图标、颜色和文字；技术全名与完整原因在行详情中查看。`L7ProbeStatus` 区分授权、业务证据及查询失败；未知定义不映射成不支持，特殊访问未授权显示灰色。

`L7ProbeLog` 在采集工作线程写入 `logs/probe-latest.log`，保留 `probe-previous.log`，每份按实际 UTF-8 限制为 80 KiB，独立原子保存，不争用连接日志文件。记录使用短批次号、时间、结果与白名单字段，并继续通过统一脱敏规则；权限名和技术字段保留原名，敏感字段只遮盖值，原始协议载荷继续排除。完整 JSON 与日志分别保存，导出与手动上传纳入采集日志；上传预算优先保留采集记录，避免被大量会话日志挤掉。进入页面和收集动作不发网络请求。当前完成基础扫描及日志归并；实车问题复现、Hook 和 USB 主动测试仍按后续批次实施；原生热点一键操作见连接约束，尚待实车验证。

`L7DebugTasks` 由 Activity 持有，首页收集、结果页重新收集/单项复查和两处上传入口复用同一任务窗口。`L7TaskProgressDialog` 区分执行、停止等待、失败重试和结果；200 ms 刷新进度，关闭或后台移除回调。开始操作防重复，普通页面刷新不重启任务；返回/右上角关闭先确认终止，点击外部不关闭。收集停止只停止后续查询并拒收迟到结果，不强杀系统调用；上传关闭当前连接并阻止后续批次。配置重建只重新绑定仍在运行的任务；进入后台停止、销毁释放窗口，回来不自动续传。

悬浮日志使用共用开关行，状态由服务实际显示结果回填；程序回填不会再次触发用户回调。权限引导取消、启动失败保持关闭，关闭浮窗或权限撤销同步更新。

空快照进入 EMPTY 状态，不发送摘要、不写成功历史。HTTP 非成功响应最多读取 4097 字节，只将已知的日志流删除中错误映射为本地化提示，不保存或展示响应原文。

`RemoteLogHistory` 只在完整报告被服务器确认后保存成功时间与条数，不记录地址、认证或设备身份；记录独立于服务器配置，失败、取消和修改配置不覆盖。两处上传入口读取同一摘要，执行进度与失败原因留在任务弹窗；重启后仍显示上次成功信息，不补造旧版记录。

清空操作复用采集工作线程并与采集互斥；运行日志写入使用代次检查，清空后旧队列不能回填。两种清空都取消上传并丢弃旧重试快照，清空期间禁止新上传。清空报告限定本地报告文件及其原子写入副本，保留运行日志和用户导出。LogView 读取、筛选和复制不触发上传，关闭时释放线程与快照。旧版本已过滤掉的内容无法补回，新记录才适用当前脱敏规则。

### OpenObserve 打包默认值

将根目录 [.env.example](../.env.example) 复制为 `.env`，设置 `L7_LOG_SERVER_URL` 和 `L7_LOG_AUTHORIZATION`。URL 支持 `/api/组织/{HeadUnit}-{DeviceID}/_json` 或 `/api/组织/{DeviceID}/_json`，占位符只允许位于流名位置；也兼容控制台普通示例。实际上传保留服务器、代理前缀与组织，再替换流名；花括号原样保存到打包资源，不执行 shell 插值。认证值为完整的 `Basic <Base64(用户名:写入凭据)>`，使用具有目标设备日志流写入权限的凭据。显式环境变量优先，Docker 构建支持。配置只提供默认值，不触发上传。内置地址通过 RemoteLogEditor 与展示分离，列表仅显示 `*****`，弹窗不向可复制的输入文本填入内置地址或已有认证。空字段解析为保留原值；未修改不保存覆盖值，避免冻结后续打包默认值。更换地址不得自动复用原认证。

协议使用 OpenObserve 官方 [JSON 批量写入接口](https://openobserve.ai/docs/reference/api/ingestion/logs/json/) 和 [Basic 认证](https://openobserve.ai/docs/reference/api/)。每条日志一个事件，一次手动任务按 UTF-8 JSON 实际字节限制为 1 MiB，每批最多 256 KiB / 1000 条；最多保留 5000 条日志另加整理摘要。按八份运行日志、内存和两份采集日志顺序收集，预算不足先移除较旧运行记录；不按文本去重，保留重复故障证据。`source` 标明来源，`batch_index/batch_count` 标明批次，整理摘要记录省略、遮盖、原始载荷排除、行截断和文件尾部裁剪数量。每行最多 4096 字符，超限附加标记。`report_id` 与 `event_id` 在手动重试时保持不变，但不承诺服务端自动去重。每批只有响应目标流的 `successful` 等于发送数量且 `failed=0` 才推进；部分拒收立即停止并报错，手动重试从未确认批次继续，全部批次完成才显示成功。请求不跟随重定向，不打印认证值或响应正文。

`HeadUnit` 取与诊断中 Head unit 相同的 `Build.MANUFACTURER` 和 `Build.MODEL`，转为小写安全字符并限制长度；缺失时使用 `head_unit`。`DeviceID` 优先基于 Android ID，不可用时尝试标准序列号 API，仍不可用则生成本地随机值；通过带包名、用途版本及来源类型的 SHA-256 生成 20 位十六进制哈希，分四组显示。旧编号或型号变化保留已有哈希，仅更新型号前缀。只持久化名称与哈希结果，与服务器配置分开保存；不读取 VIN、MAC 或 IMEI，不保存原始唯一标识。名称仅用于请求 URL 的流名位置，JSON 记录不包含 `device_id`；按 OpenObserve 的规范化流名验证回执并显示名称。它用于日志关联，不作为授权或身份验证依据；正常覆盖升级及重试不改变哈希，恢复出厂、更换签名、用户或随机回退后清除数据可能改变哈希。

上传工作线程不持有 Activity，不占音视频线程；退出、撤回或配置变化取消任务，迟到结果按代次隔离。没有自动采集服务、定时上传或自建日志后台。APK 默认凭据可被提取，应限制写入权限并按测试批次轮换；根目录 `.env` 和真实服务地址不进入公开文档或 Git。

### 认证与签名

默认认证输入为 `.private/auth-assets/offline-mfi/identity.pk8` 与 `certificate.p7b`，Git 忽略。可通过 `DIPLAY_AUTH_ASSETS_DIR=/absolute/path/to/runtime-assets` 指定替代目录；仅运行时只读挂载到 `/run/l7-auth`，不写入镜像。材料不随源码分发，交付包与输入的一致性在本地检查。

发布通过本机安全方式设置 `ANDROID_KEYSTORE_PATH`、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`，运行 `bash scripts/build-android-docker.sh --release`。入口执行 `:mobile:assembleStandaloneRelease`，输出 `mobile/build/outputs/apk/release/mobile-release.apk`；keystore 只读挂载，缺参数即停止，发布同样使用一次性容器。

Android 签名与 MFi 认证分别管理；同包名或公开证书不赋予原厂身份和系统权限。用容器内 `apksigner verify --print-certs` 检查产物，安装前核对签名与版本码。凭据与报告规则见 [SECURITY.md](../SECURITY.md)。
